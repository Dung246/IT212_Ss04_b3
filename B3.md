1. Phân tích lý do prompt thô dễ bỏ sót lỗi

Prompt thô "Mã này bị lỗi gì?" quá ngắn và thiếu ngữ cảnh nên AI dễ chỉ kiểm tra các lỗi cú pháp 
(Syntax Error) hoặc lỗi biên dịch (Compile Error).
Trong trường hợp này:
   Mã nguồn không có lỗi cú pháp.
   Chương trình biên dịch và chạy bình thường.
   Không có Exception hay Stack Trace.
   Lỗi nằm ở logic của thuật toán (Logic Error).

Cụ thể, vòng lặp bên trong được viết:for (int j = i; j < arr.length; j++)
Do j bắt đầu từ i, nên ngay lần đầu tiên: arr[i] == arr[i]luôn đúng.

Ví dụ: int[] arr = {1, 2, 3, 4};

Quá trình thực hiện:
i = 0
j = 0
arr[0] == arr[0] → đúng
return 1

Trong khi mảng không hề có phần tử trùng lặp, hàm vẫn trả về 1.

Nếu prompt không yêu cầu:
   phân tích thuật toán,
   chạy thử với ca kiểm thử,
   tìm lỗi logic,
thì AI có thể kết luận sai rằng mã không có lỗi vì chương trình vẫn biên dịch và thực thi.

2. Nội dung Prompt tối ưu
Bạn hãy đóng vai trò là một Code Auditor có nhiều kinh nghiệm về Java và phân tích thuật toán.
Tôi có đoạn mã Java sau:

public class DuplicateFinder {

    // Lỗi logic: j bắt đầu từ i dẫn đến việc phần tử tự so sánh với chính nó
    public static Integer findDuplicate(int[] arr) {

        for (int i = 0; i < arr.length; i++) {

            for (int j = i; j < arr.length; j++) {

                if (arr[i] == arr[j]) {
                    return arr[i];
                }

            }

        }

        return null;
    }
}

Ca kiểm thử: int[] arr = {1, 2, 3, 4};
Kết quả mong muốn: null
Nhưng chương trình lại trả về: 1

Yêu cầu:
   Đóng vai trò là Code Auditor.
   Phân tích từng bước quá trình thực thi với ca kiểm thử trên.
   Chỉ ra nguyên nhân gốc rễ của lỗi logic.
   Giải thích vì sao lỗi này không bị trình biên dịch phát hiện.
   Đề xuất cách sửa tối ưu bằng cách sử dụng HashSet.
   Nâng độ phức tạp thuật toán từ O(N²) xuống O(N).
   Giữ nguyên chức năng tìm phần tử trùng lặp đầu tiên.
  Trả về mã Java hoàn chỉnh trong khối Markdown và giải thích ngắn gọn.

3. Mã nguồn Java đã sửa sử dụng HashSet
   
import java.util.HashSet;
import java.util.Set;
public class DuplicateFinder {

    public static Integer findDuplicate(int[] arr) {
        Set<Integer> seen = new HashSet<>();

        for (int value : arr) {
            // Nếu phần tử đã tồn tại trong HashSet
            if (!seen.add(value)) {
                return value;
            }
        }

        // Không có phần tử trùng lặp
        return null;
    }

    public static void main(String[] args) {
        int[] arr1 = {1, 2, 3, 4};
        int[] arr2 = {1, 2, 3, 2, 5};

        System.out.println(findDuplicate(arr1)); // null
        System.out.println(findDuplicate(arr2)); // 2
    }
}
